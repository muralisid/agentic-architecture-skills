# Choose where to start

Select useful work that can be evaluated, supplied with reliable information, and operated responsibly.

Start with a process that has a clear owner and a result people can judge. A visible business problem is more useful than a general ambition to “add agents”.

## Describe the work

Write down the request, the current steps, the information used, the decisions made, and the result. Include exceptions. Identify the part that requires adaptive investigation and the part that can stay a fixed workflow.

## Apply three checks

1. **Can we evaluate it?** Agree what a correct and useful result looks like, with realistic examples.
2. **Can we protect its actions?** Identify actions involving access, money, physical safety, or official records. Place the controls outside the model.
3. **Can we supply reliable evidence?** Check access, quality, freshness, and ownership of the information.

An idea that fails a check goes into a preparation list. It may need clearer outcomes, better interfaces, or improved data before an agent is useful.

## Assess the organization

Use the [readiness assessment](https://www.agenticarchitectureskills.com/library/frameworks/readiness-assessments). Keep the six dimensions separate: a strong score in one area does not compensate for a missing control elsewhere. The complete assessment retains its 24 questions and deeper evidence-based mode.

## Choose a first portfolio

Use the [use-case portfolio](https://www.agenticarchitectureskills.com/library/frameworks/use-case-portfolio) to compare expected value, operating cost, risk, and supervision capacity. A collection of individually attractive cases can still exceed the team’s ability to review exceptions.

## Set the trial boundary

Choose a narrow scope, representative cases, a responsible owner, and explicit stop conditions. Compare against the current process. Keep a way to return to that process while the proposed system is evaluated.
